# Current SQLite business recovery points

A populated sealed namespace uses an encrypted SQLite checkpoint, not the retired JSONL table exporter. The existing serial backup scheduler and signed chunk transport remain in use; storage peers receive only ciphertext and independently check its size and SHA-256 before retaining the newest two verified generations. No new container is required.

The Master holds the shared sealed-tree publication fence, creates a consistent SQLite image using SQLite VACUUM INTO, authenticates its namespace and copies authenticated lyric ciphertext. Audio, video and recordings are excluded. The full database retains business configuration, associations, ordering, IP policy and WebRTC/audit state. Pending resource transactions defer capture. Capture is bounded to 256 MiB of database and 512 MiB total, and requires at least 1 GiB plus two estimated captures and 64 MiB of free disk. A refused or failed capture does not change node connectivity or discard the previous verified point.

A random artifact key encrypts 64 KiB authenticated frames; only the existing Master vault can unwrap it. The authenticated terminal frame rejects truncation, reordering and appended bytes. Deployment identity/key files are not exported to untrusted storage. Recovery therefore requires retained Master secrets and the surviving media resources; these state points are not a replacement for deployment-identity protection or media replication.

On that existing Master, `frontiercloud verify-business-point --file /private/point --sha256 <independently-retained-digest> --generation <exact-generation> --target /private/new-directory` verifies and extracts into a new private directory. It checks the independent digest/size, frame authentication, SQLite integrity/schema/Master identity, namespace authentication and every included lyric ciphertext. It refuses an occupied destination and removes a failed extraction. It never replaces live state or promotes a storage node. A controlled live restore remains a separate maintenance operation.

The Admin GUI separates node inventory, public ingress/transport, recovery-point health and node settings. Enabling Backup remains an explicit node setting. A Master-side build failure is recorded even if no receiving manifest reached the peer; the last successful generation is preserved. Normal cadence is 24 hours, with retries after approximately five minutes.
